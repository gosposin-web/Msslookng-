# ZAVOD 1.0 · облачная панель историй

До 15 аккаунтов с отдельными очередями, аудиторией и паузами Telegram. Для новых заданий: автор с Premium — только просмотр, без Premium — просмотр и 👍; неизвестный статус — только просмотр. В настройках выбранного аккаунта можно редактировать био, создавать публичные каналы и закреплять свой канал в профиле.

Личный инструмент с адаптивным интерфейсом на русском языке. Рабочая панель и Telegram-клиент размещаются вместе на одном сервере. Управление — из браузера телефона; задания выполняет сервер, независимо от открытой страницы.

## Потоковый парсинг и просмотр

Кнопка «Парсить и смотреть» создаёт одно задание `masslook`. Оно загружает небольшую страницу, проверяет истории и сразу обрабатывает каждые 5 авторов с активными историями, затем продолжает поиск. Остаток меньше пяти обрабатывается в конце чата. Чаты одного аккаунта идут последовательно, чтобы импорт из 200 чатов не создавал 200 временных баз одновременно.

Новые записи без историй и обработанные временные пользователи удаляются. Ранее сохранённая аудитория и ручные списки сохраняются. До конца задания остаются только ID для дедупликации; подтверждения просмотров и неопределённые попытки сохраняются отдельно для защиты от повторов. В задании показаны проверенные люди, найденные авторы, подтверждённые просмотры историй, просмотренные авторы и реакции. Неопределённая попытка не увеличивает счётчик просмотров. Старое задание `scan` остаётся только сбором и проверкой; оно не начинает просмотр после обновления.

`POST /api/sources/{id}/masslook` принимает `delay` от 5 до 300 секунд. При файловом импорте `auto_view=true` включает этот режим, `start_scans=false` только сохраняет чаты. По умолчанию API сохраняет прежнее поведение сбора; интерфейс явно включает новый режим.

## Прокси аккаунтов

Общий список поддерживает SOCKS5 и HTTP CONNECT. Лимита на число сохранённых прокси нет; список загружается страницами. В каждом из 15 слотов выбирается прямое подключение либо конкретный прокси, в том числе перед импортом tdata. По умолчанию один прокси назначается только одному аккаунту. Чтобы назначить его нескольким аккаунтам, владелец явно включает общий доступ у этого прокси.

Логин и пароль зашифрованы тем же ключом приложения, что и сессии; ответы API их не содержат. Пустые поля при редактировании сохраняют прежние значения, удаление авторизации включается отдельным флажком. Для облачного подключения нужен публичный IP или DNS-адрес; проверенный IP фиксируется на время соединения. Настройки применяются к обоим клиентам импорта и к последующим запросам. При ошибке выбранного прокси прямое подключение автоматически не включается. Настройки занятого соединением аккаунта меняются после завершения запроса.

`GET/POST /api/proxies`, `PATCH/DELETE /api/proxies/{id}` управляют списком; `POST /api/account/proxy` с `proxy_id` или `null` назначает подключение только выбранному слоту из заголовка `X-Story-Account`. `/api/state` объявляет `max_accounts=15` и `module_version=2`.

## Обновление панели и восстановление очереди

Панель использует приватные условные запросы для состояния и аудитории. Если данные не изменились, сервер возвращает пустой ответ 304; в памяти браузера остаётся не более 12 ответов. Смена аккаунта, запись и выход очищают этот кэш. Запоздавший ответ, начатый до изменения данных, не заменяет новое состояние. Ошибки сети остаются видимыми. Сервер заново проверяет авторизацию и данные при каждом запросе; активные истории и просмотры за 24 часа пересчитываются.

Счётчики просмотров для страницы из 100 пользователей читаются одним общим запросом. Подтверждённые просмотры и неопределённые попытки остаются раздельными.

После перезапуска автоматически продолжаются только безопасные этапы поиска и проверки пользователей, прерванные во время работы. Ручные паузы, ожидание Telegram и этапы просмотра/реакций сохраняют прежние ограничения. Если первое задание держит очередь чатов на паузе, панель показывает его причину, число ожидающих чатов и кнопку продолжения. Продолжение не сбрасывает FloodWait, а неподтверждённые просмотры пропускаются.

## Что реализовано

- Вход в панель по паролю, защищённая cookie, CSRF и ограничение попыток входа.
- Импорт ZIP с tdata активного аккаунта Telegram Desktop. Для облака создаётся отдельная авторизация через параметры собственного приложения Telegram; исходный ключ Desktop не используется для постоянной работы.
- Локальный код-пароль tdata и пароль двухэтапной проверки передаются только на время импорта. Исходный архив и извлечённые файлы удаляются после попытки импорта.
- В разделе «Чаты» можно загрузить TXT/CSV до 512 КБ и 200 уникальных чатов за один импорт. TXT: один `t.me/имя`, `@username`, ID или invite-ссылка на строку. CSV поддерживает столбцы «Ссылка», `url`, `username`, `chat_id`, запятую, точку с запятой и табуляцию; кодировки UTF-8, UTF-16 с BOM и Windows-1251. Дубликаты пропускаются, для неверных строк выдаётся отчёт. В панели хранится до 500 источников.
- Сбор можно сразу поставить в очередь для каждого чата. Повторная отправка того же запроса не создаёт новые задания. У импорта есть общая пауза, продолжение и остановка; недоступный чат отмечается отдельно. Для уже выполняющегося или приостановленного сбора второе задание не создаётся. Приложение не вступает в группы автоматически.
- Ошибка всей авторизации приостанавливает очередь. Ожидание Telegram сохраняется при паузе и перезапуске. Результаты старого запроса не записываются поверх заново восстановленного облачного сохранения; неоднозначные просмотры не повторяются автоматически.
- Во вкладке «Аккаунт» можно отдельно изменить имя и фамилию, username (включая его удаление) и аватарку. Изменения отправляются в Telegram. Фото JPG/PNG/WebP до 5 МБ проверяется, обрезается по центру и сохраняется без EXIF.
- Перед созданием облачной сессии проверяются авторизация и заморозка исходного аккаунта; после входа проверяется новая сессия. Ошибки импорта содержат код и пояснение для отозванной сессии, блокировки, удаления, заморозки, паролей, параметров API и ожидания Telegram. Дата `freeze_until_date` показана как срок до возможного удаления аккаунта, а не срок разморозки.
- До 500 источников: группы по @username, t.me-ссылке, ID или приглашению в группу, где аккаунт уже состоит.
- Сбор доступного списка участников или авторов последних доступных сообщений (до 5 000 сообщений). Telegram может вернуть неполный список; обход скрытой аудитории не реализован.
- До 5 000 пользователей за задание; дедупликация между источниками.
- Реальная проверка активных историй, доступных аккаунту, без обхода приватности.
- Таблица, поиск, фильтры, выбор пользователей и экспорт CSV без ключей доступа.
- Отдельный явный запуск регистрации просмотров выбранной аудитории. Перед просмотром истории проверяются повторно. Приложение регистрирует просмотры через API и не воспроизводит видео в интерфейсе.
- Очередь, пауза, продолжение, остановка и журнал событий. Запрос FLOOD_WAIT блокирует все задания аккаунта до указанного Telegram срока; ручное продолжение не сбрасывает эту паузу.
- Подтверждённые и потенциально выполненные просмотры не повторяются. Неопределённый результат сетевого запроса сохраняется отдельно и не считается успешным просмотром.
- Внутренний предел — 200 историй за скользящие 24 часа, включая неподтверждённые попытки для ограничения активности. Это ограничение приложения, а не опубликованный безопасный лимит Telegram.
- Сессия и access_hash хранятся зашифрованными; аудитория и очередь — в SQLite на постоянном диске. Клиентские ответы и CSV не содержат сессию и access_hash.

## Бесплатное облачное размещение

Бесплатный режим использует Render Free для Python и личный Site для интерфейса, входа через ChatGPT и зашифрованных контрольных точек в R2. Платный диск и бесплатная база с истечением через 30 дней не нужны.

В Render подготовлено размещение отдельной ветки `story-cloud-free` репозитория `gosposin-web/Msslookng-`, из каталога `story-cloud/`. Существующая ветка `main` и сервис `msslookng-telegram` не изменяются. Автодеплой новой службы выключен.

Доступ к панели остаётся только у владельца. Её сервер пересылает в Python только нужные заголовки приложения и отдельный служебный ключ; cookie входа ChatGPT и токены Site в Render-запросы браузера не передаются. Авторизация в Telegram выполняется после загрузки архива владельцем; проверка реального аккаунта без его архива не проводилась.

Сессия и прогресс сохраняются в зашифрованной копии SQLite вне эфемерного сервера. Перед необратимым запросом просмотра намерение обязательно записывается в облако. При недоступном сохранении новые просмотры приостанавливаются. Условная запись по ETag и блокировка экземпляра предотвращают конкурирующую работу при перезапуске. Исходный tdata-архив в R2 не сохраняется.

### Ограничения Free

Render Free может заснуть после 15 минут без входящих запросов и удаляет локальные файлы при сне, перезапуске или новом развёртывании. Следующее открытие панели пробуждает его; запуск занимает около минуты. Сессия и очередь восстанавливаются из облачной копии. Задания не выполняются, пока сервер спит. Просмотр с неясным исходом требует ручного продолжения и не повторяется автоматически. Искусственные пинги для обхода сна не используются.

Тариф предоставляет 750 часов Free на всё рабочее пространство в месяц. Трафик и сборки также учитываются в общих бесплатных квотах Render: при привязанном способе оплаты превышение некоторых квот может тарифицироваться. Не включать платный план, диск или платные базы; использовать небольшие пробные аудитории. Обещание безусловной круглосуточной бесплатной работы не даётся.

### Переменные сервера

- `PYTHON_VERSION=3.12.14`, `DATA_DIR=/tmp/story-cloud`, `FREE_MODE=true`, `COOKIE_SECURE=true`.
- `PUBLIC_ORIGIN` — точный HTTPS origin личного Site.
- `STORY_BRIDGE_SECRET` — общий случайный секрет сервера и личного Site, только в секретах платформ.
- `APP_ENCRYPTION_SECRET` — постоянный случайный ключ; после подключения аккаунта его нельзя менять без переноса шифрованных данных.
- `SNAPSHOT_SITE_URL` — тот же личный Site.
- `SNAPSHOT_SITE_TOKEN` — существующий служебный доступ только к этому личному Site.
- `ADMIN_PASSWORD` — случайный резервный пароль прямого API; в обычном режиме используется вход через ChatGPT.

На Site задаются секрет `STORY_BRIDGE_SECRET` и HTTPS-адрес `BACKEND_URL`. Site использует привязку R2 `BUCKET`. `build_cloud.py` собирает интерфейс и шлюз в `dist/server/index.js`.

tdata — формат Telegram Desktop. Нужен имеющийся архив собственного аккаунта; мобильный Telegram его не создаёт. Во время импорта исходная Desktop-сессия должна быть закрыта. Для пробного подключения по умолчанию используются опубликованные параметры `API.TelegramDesktop` из opentele. API ID и API Hash вводить не обязательно. Свои параметры с https://my.telegram.org/apps можно указать в дополнительных настройках; вводить следует полную пару. `TELEGRAM_USE_PUBLIC_API=false` отключает публичные параметры. Если включена двухэтапная проверка, потребуется её пароль. Публичные параметры не дают гарантии успешной авторизации или отсутствия ограничений; для собственного приложения Telegram требует получить свой api_id.

При отключении аккаунта приложение пытается завершить облачную авторизацию; если Telegram недоступен, следует завершить её в «Устройствах» Telegram. Удаление из приложения не означает удаление резервных копий провайдера.

Платный вариант оставлен отдельно в `render.yaml`; для текущего бесплатного режима используется `render-free.yaml` или прямая конфигурация Render с `plan=free`.

Офлайн-проверки включают полный цикл создания и разбора искусственного tdata с код-паролем и без него. Это проверяет формат архива и служебные карты аккаунта, но не заменяет реальный вход владельца.

## Проверка разработки

```sh
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
node --check app/static/app.js
python build_cloud.py
npm test
```

Для локальной разработки: задать переменные из `.env.example` в окружении и запускать `uvicorn app.main:create_app --factory --workers 1`. На локальном HTTP допускается `COOKIE_SECURE=false`; в облаке оставлять `true`. `Dockerfile` включает системные зависимости QtCore и сборку TgCrypto; графическая среда не нужна. Docker-образ собран и запущен в Render. Локально Docker недоступен.

Реальные запросы к Telegram выполняются только после загрузки tdata в работающую панель. Приложение не подписывается на чаты и не выполняет рассылки. Ожидание Telegram сохраняется отдельно для каждого аккаунта. Смена прокси не сбрасывает это ожидание.

## Пользователи по юзернейму

В разделе «Аудитория» доступно поле одного пользователя и кнопка «Загрузить список». Принимаются `@username`, `username`, `t.me/username` и ссылки на профиль. Файл TXT/CSV — до 200 уникальных юзернеймов, 512 КБ; поддержаны UTF-8/BOM, UTF-16 с BOM и CP1251, разделители CSV — запятая, точка с запятой или табуляция, столбец `username`. Нужен подключённый Telegram-аккаунт.

`POST /api/people` принимает JSON `username`, `request_id`; `POST /api/people/import` — multipart `file`, `request_id`. Принятый список создаёт одно задание `people_import` с устойчивым курсором. Повтор того же запроса не создаёт второе задание. Каждый юзернейм разрешается отдельно, затем проверяются доступные истории. Боты, чаты, собственный и удалённые аккаунты пропускаются с пояснением. Ошибка конкретного имени не останавливает список; отзыв сессии приостанавливает всю очередь, FloodWait сохраняет обязательную паузу.

Люди объединяются по Telegram ID с аудиторией чатов. Фильтр «Добавленные по юзернейму» показывает ручной импорт. В разделе «Задания» доступны прогресс, первые 20 причин пропуска, пауза, продолжение и остановка. Импорт не отмечает истории просмотренными: просмотр запускается владельцем отдельно. Незавершённый импорт восстанавливается из зашифрованного снимка после сна сервера.

## Автоматическое подключение после сна

При открытии личной панели браузер загружает публичную страницу `/wake` сервера в отдельном фоновом фрейме. Эта страница проверяет только `/health` без авторизации и сообщает готовность через `postMessage` только фиксированному origin панели. Панель проверяет origin и окно отправителя, затем использует обычный защищённый шлюз. Если фоновое пробуждение не подтвердилось за 45 секунд, открывается обычная страница запуска, которая после готовности автоматически возвращает в личный Site. Маркер возврата предотвращает цикл переходов и сбрасывается после успешного подключения.

Проверки соблюдают `Retry-After`, продолжаются автоматически, пока открыта страница, и восстанавливаются после возврата Safari из фона или восстановления сети. Неактивная вкладка не опрашивает сервер. Повторное подключение после сетевого сбоя заново запускает проверку готовности. Публичная страница не принимает произвольный адрес возврата и не раскрывает данные аккаунта. Возможность встраивания разрешена только для `/wake` и только настроенному origin панели; API и рабочий интерфейс сохраняют защиту от встраивания. Фоновых заданий для постоянного удержания бесплатного сервера активным нет.
